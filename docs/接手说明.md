# 同事接手说明

## 先明确版本

当前版是 runtime。不要将 recovered-source 的构建产物发布到现网，因为它是早期版本，缺少后期功能。建议先按根目录 README 运行隔离演示和验证，确认拿到完整包后再开展维护。

## 当前代码的主要入口

| 任务 | 文件位置 |
| --- | --- |
| 启动与依赖 | runtime/server.js、runtime/package.json、runtime/package-lock.json |
| 当前页面 | runtime/.next/server/app/page.js、runtime/.next/static/chunks/app/ |

编译文件不具备原始 TS 类型、组件组织与完整构建工程。后续若要恢复完整开发能力，需要将当前逻辑迁移回正常源码工程，逐项比对功能；仅格式化 JS 或给编译目录添加 build 脚本不能解决此问题。

## 环境资料另行交接

请管理员提供开发环境数据库账号、对应 OSS 桶与测试权限、模型服务账号、工作站与采集服务的部署资料、反向代理/进程管理配置。只在团队安全渠道交接，不放入 Git 仓库。先使用独立开发库和素材前缀，避免测试写入真实数据。

## 交接证据

- `live-verification.json`：当前服务器发布与运行文件核对。
- `../checks/runtime-smoke-results.json` 与 `recovered-source-smoke-results.json`：本地核心测试结果。
- `source-build.log`：恢复源码构建结果。
- `../MANIFEST.json`：压缩包文件大小与 SHA-256；不包含清单自身。
- `../VALIDATION.json`：本次交付检查范围和未覆盖项目。

没有真实业务数据或密码，缺少这些环境资料时不能宣称完整现网功能全部可运行。
