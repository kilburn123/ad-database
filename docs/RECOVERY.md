# 源码恢复与验证边界

## 结论

本次从原开发电脑的 Codex 归档工具记录中恢复出历史 React/TypeScript 工程。恢复截止点为 2026-07-03 08:00 UTC（北京时间 16:00）。工程不是从当前压缩 JavaScript 猜写的替代版本，主要来自原创建与修改记录；为使其可验证，另外补齐了 PostgreSQL 依赖、类型依赖、版本约束及新锁文件。

恢复出的 14 个原项目源码及配置文件可以通过 Next.js 生产构建，核心广告读写可以运行。**这不证明它与当时工程逐字节相同，也不证明它包含当前线上所有功能。** 历史补丁回放仍有 3 条不能自动应用；本次以完整文件、类型检查、构建和核心测试作为交接证据。

后期历史记录中存在缺失上下文、直接修改编译产物和不同项目分支。虽然找到更多片段，仍不足以组成当前版本完整页面与后端源码，因此没有把不完整拼接文件放入可开发目录。

## 后续接手优先级

先由业务方确认继续维护当前功能，还是以早期源码为基线开发。如果必须完整重建当前版本，需要继续取得后期完整源码或逐项迁移编译产物里的业务逻辑并对照线上行为验证。新功能开发应在独立分支、独立数据库进行，建立版本化迁移与回归用例。现有访问控制及修改/删除接口需要专项评审后再对外部署。
